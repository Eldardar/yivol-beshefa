# פריסה

1. התקינו Node 22 והריצו `npm ci`.
2. הגדירו `DATABASE_PATH` לנתיב מוחלט על אחסון מתמיד והרשאות 0700 לספרייה.
3. גבו את SQLite (כולל WAL/SHM או באמצעות SQLite backup) לפני שינוי גרסה.
4. הריצו `npm run db:migrate`, `npm run build`, ואז `npm start` מאחורי reverse proxy עם HTTPS. היישום נכשל במכוון בייצור אם `DATABASE_PATH` חסר או יחסי.
5. הגדירו Health check ל-`/login`; הפעילו תהליך יחיד בעת שימוש במגביל הכניסה המובנה. הגדירו `TRUST_PROXY=1` רק אם ה-proxy המהימן מנקה כותרת נכנסת ומוסיף את כתובת הלקוח בסוף `X-Forwarded-For`. בפריסה מרובת תהליכים החליפו את המגביל במאגר משותף עם TTL.
6. צרו מנהל עם משתני `SEED_ADMIN_*`, הריצו `npm run seed`, ומחקו אותם מסביבת הריצה.

## שחזור וחזרה
עצרו כתיבות, החזירו את קובץ הגיבוי והגרסה הקודמת, הריצו `PRAGMA integrity_check;` ו-`PRAGMA foreign_key_check;`, בנו והפעילו מחדש. המיגרציות מצטברות; אין לבצע downgrade עיוור. בצעו בדיקת שחזור תקופתית הכוללת את קובצי WAL/SHM או SQLite backup עקבי.

## אימות
בדקו HTTPS, כותרות, כניסה/יציאה, הפרדת מנהל וקוטף, יצירת טיוטה/פרסום, הופעת הודעה, זמינות ודוח מוביל. ניטור אינו רשאי לרשום סיסמאות, cookies או גוף טפסים.
